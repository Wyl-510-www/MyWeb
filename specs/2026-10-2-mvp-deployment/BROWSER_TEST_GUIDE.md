# 浏览器测试指南

本文档提供详细的浏览器测试步骤，用于验证 MVP 在真实浏览器环境中的表现。

---

## 测试环境

**本地服务器**: http://localhost:8000
**推荐浏览器**: Chrome (最新版本)
**测试工具**: Chrome DevTools

---

## Phase 1: 桌面端测试 (1920px)

### 步骤 1：打开 Chrome 开发者工具

1. 打开 Chrome 浏览器
2. 访问 http://localhost:8000
3. 按 F12 打开 DevTools
4. 点击 Toggle Device Toolbar (Ctrl+Shift+M) 或点击顶部工具栏的手机图标
5. 在顶部选择 "Responsive"
6. 设置宽度为 1920px，高度为 1080px

### 步骤 2：测试首页 (index.html)

**访问**: http://localhost:8000/index.html

**检查清单**:
- [ ] 导航栏布局正常（Logo 在左，导航链接在右）
- [ ] Hero 区域头像清晰显示
- [ ] Hero 区域标题和副标题居中显示
- [ ] 导航卡片为 2x2 网格布局（4 个卡片排列整齐）
- [ ] 点击导航卡片触发翻转动画
- [ ] 卡片背面显示 "查看详情" 链接
- [ ] Footer 布局正常，联系信息显示清晰
- [ ] 页面无明显布局错位或重叠

**性能检查**:
1. 打开 Console 面板，检查是否有错误
2. 打开 Network 面板，刷新页面
3. 检查是否有 404 错误（红色的请求）
4. 记录 DOMContentLoaded 和 Load 时间

### 步骤 3：测试作品集页面 (portfolio.html)

**访问**: http://localhost:8000/portfolio.html

**检查清单**:
- [ ] 页面标题 "作品集" 显示正常
- [ ] 项目卡片为 2 列网格布局
- [ ] 每个项目卡片包含：标题、描述、技术栈标签、链接
- [ ] 悬停卡片时有抬升和阴影效果
- [ ] 技术栈标签样式正常（圆角、背景色）
- [ ] GitHub 链接和 Demo 链接（如有）可点击
- [ ] Footer 布局正常

### 步骤 4：测试学习笔记列表页 (notes.html)

**检查清单**:

2. 观察 URL 是否更新（例如 `?tag=JavaScript`）
3. 观察笔记卡片是否正确筛选

## Phase 5: 性能测试

### 步骤 1：Lighthouse 测试

对每个核心页面运行 Lighthouse：

1. 打开 Chrome DevTools
2. 切换到 "Lighthouse" 面板
3. 选择 "Desktop" 模式
4. 勾选 "Performance"
5. 点击 "Analyze page load"
6. 等待测试完成
7. 记录以下指标：
   - Performance Score
   - LCP (Largest Contentful Paint)
   - CLS (Cumulative Layout Shift)
   - FID/INP
   - TTI (Time to Interactive)

**需要测试的页面**:
- [ ] index.html
- [ ] portfolio.html
- [ ] notes.html
- [ ] 任意笔记详情页
- [ ] life.html
- [ ] about.html

**目标指标**:
- Performance Score > 90
- LCP < 2.5s
- CLS < 0.1

### 步骤 2：Console 错误检查

对每个页面：
1. 打开 Console 面板
2. 刷新页面
3. 检查是否有 JavaScript 错误（红色）
4. 检查是否有警告（黄色）
5. 记录所有错误和警告

### 步骤 3：Network 面板检查

对每个页面：
1. 打开 Network 面板
2. 刷新页面
3. 检查是否有 404 错误（红色请求）
4. 检查所有资源是否正常加载（CSS、JS、图片、字体）
5. 记录任何加载失败的资源

## 问题处理流程

如果发现问题：

1. **严重问题**（阻碍部署）：
   - 页面无法访问
   - 主要功能不工作
   - 性能严重不达标（Performance < 70）
   - 响应式严重错位
   
   → 必须立即修复

2. **中等问题**（影响体验）：
   - 轻微布局问题
   - 非关键功能异常
   - 性能未达标但接近（Performance 70-90）
   
   → 尽快修复

3. **轻微问题**（不影响功能）：
   - 小的样式调整
   - 优化建议
   
   → 可以记录在 TODO.md 中，部署后修复

---
