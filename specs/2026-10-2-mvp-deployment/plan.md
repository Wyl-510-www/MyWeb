### Phase 3: 性能测试和优化（Day 1-2）

#### 3.1 Lighthouse 测试
- [ ] 对首页运行 Lighthouse 测试
- [ ] 对作品集页面运行 Lighthouse 测试
- [ ] 对学习笔记列表页运行 Lighthouse 测试
- [ ] 对学习笔记详情页运行 Lighthouse 测试
- [ ] 对生活记录列表页运行 Lighthouse 测试
- [ ] 对关于我页面运行 Lighthouse 测试
- [ ] 记录各页面的性能指标：
  - [ ] Performance Score
  - [ ] LCP (Largest Contentful Paint)
  - [ ] CLS (Cumulative Layout Shift)
  - [ ] FID (First Input Delay)
  - [ ] TTI (Time to Interactive)

**预计时间**：1 小时

---

#### 3.2 性能优化（如果需要）
- [ ] 如果 LCP > 2.5s，检查并优化：
  - [ ] 大图片是否已压缩为 WebP
  - [ ] 是否有阻塞渲染的资源
  - [ ] 字体加载是否优化
- [ ] 如果 CLS > 0.1，检查并优化：
  - [ ] 图片是否有明确的宽高属性
  - [ ] 是否有动态插入的内容导致布局偏移
- [ ] 如果 Performance Score < 90，根据 Lighthouse 建议优化

**预计时间**：2-3 小时（根据问题严重程度）

---

#### 3.3 图片优化（如果需要）
- [ ] 检查所有图片是否已压缩
- [ ] 检查是否已转换为 WebP 格式

**预计时间**：1 小时

### Phase 4: GitHub Pages 部署配置（Day 2）

#### 4.1 准备部署分支
- [ ] 确认当前在 `master` 分支
- [ ] 运行最终构建：
  ```bash
  npm run build:notes
  npm run build:life
  ```
- [ ] 确认所有生成的文件正常
- [ ] 提交所有更改：
  ```bash
  git add .
  git commit -m "feat: MVP 内容填充和优化完成"
  ```

**预计时间**：0.5 小时

---

#### 4.2 配置 GitHub Pages
- [ ] 推送到 GitHub：
  ```bash
  git push origin master
  ```
- [ ] 进入 GitHub 仓库设置（Settings → Pages）
- [ ] 选择部署分支（`master` 或 `main`）
- [ ] 选择部署目录（根目录 `/`）
- [ ] 保存配置
- [ ] 等待部署完成（通常 1-2 分钟）

**预计时间**：0.5 小时

---

#### 4.3 验证部署
- [ ] 访问 GitHub Pages 提供的 URL（`https://<username>.github.io/<repo-name>/`）
- [ ] 测试所有页面是否正常访问
- [ ] 测试 HTTPS 是否正常
- [ ] 测试图片和静态资源是否正常加载
- [ ] 测试导航和链接是否正常工作
- [ ] 使用 Chrome DevTools 检查控制台是否有错误

**预计时间**：0.5 小时

---

#### 4.4 可选：配置自定义域名
如果需要配置自定义域名：
- [ ] 在 GitHub Pages 设置中添加自定义域名
- [ ] 在域名服务商配置 DNS 记录：
  - [ ] CNAME 记录指向 `<username>.github.io`
  - [ ] 或 A 记录指向 GitHub Pages IP
- [ ] 在项目根目录创建 `CNAME` 文件：
  ```
  your-domain.com
  ```
- [ ] 提交并推送：
  ```bash
  git add CNAME
  git commit -m "chore: 添加自定义域名"
  git push origin master
  ```
- [ ] 等待 DNS 生效（可能需要几小时到 24 小时）
- [ ] 在 GitHub Pages 设置中勾选「Enforce HTTPS」

**预计时间**：1-2 小时（包括 DNS 等待时间）

## 风险和缓解措施

### 风险 1：性能测试不达标
**缓解措施**：
- 提前进行图片压缩和优化
- 优先修复影响 LCP 和 CLS 的关键问题
- 如果优化困难，可以调整验证标准（例如 Performance Score > 85）

### 风险 2：GitHub Pages 部署失败
**缓解措施**：
- 提前检查 GitHub Pages 配置文档
- 确认所有静态资源路径正确（相对路径 vs 绝对路径）
- 如果部署失败，可以考虑使用 Netlify 或 Vercel 作为备选方案

### 风险 3：真机测试发现严重问题
**缓解措施**：
- 提前使用 Chrome DevTools 进行充分测试
- 如果真机测试发现问题，优先修复影响用户体验的关键问题
- 次要问题可以记录在 TODO.md 中，上线后修复
